# GK 산업 콘텐츠 모델

초기 콘텐츠는 정적 JSON으로 관리한다. 아래 구조는 구현 전 기획 기준이며, 실제 필드명은 개발 단계에서 승인된 범위 안에서 확정한다.

## 1. 시공 사례 (`content/cases.json`)

사례 배열은 JPA의 `Page` 구조를 참고해 `content` 안에 둔다. 페이지 크기·페이지 번호·정렬 같은 고정 조회 조건과 `totalElements`·`totalPages` 같은 결과값은 JSON에 저장하지 않고 함수가 처리한다.

| 루트 필드 | 의미 | 초기값 |
| --- | --- | --- |
| content | 모든 시공 사례 배열 | 실제 사례 9건 |

페이지 번호는 내부에서 0부터 시작하며, 화면에는 항상 1을 더해 표시한다.

| 필드 | 필수 | 의미 | 예시 |
| --- | --- | --- | --- |
| id | 예 | 1부터 증가하는 사례 고유 숫자 | `1` |
| title | 예 | 지역·현장 유형·공법 제목 | `화성시 공장 에폭시` |
| tags | 예 | 현장 유형과 공법 태그 배열 | `["공장", "에폭시"]` |
| location | 예 | 공개용 장소 | `화성시 공장` |
| description | 예 | 상세 시공 내용 | `…` |
| productIds | 예 | 사용 제품명 배열. `null` 불가 | `["크리트"]` |
| images | 예 | 여러 장의 시공 사진 배열 | `[{"src":"/…","alt":"…"}]` |

### 대표 이미지 규칙

- 시공 사례는 목록 카드와 웰컴 페이지에 사용할 대표 사진의 위치를 `thumbnailIndex` 숫자로 지정한다.
- 화면은 `images[thumbnailIndex]`를 대표 사진으로 사용한다. 예: `"thumbnailIndex": 0`
- 이미지 경로와 대체 텍스트는 `images` 배열에서 한 번만 관리한다.

### 사례 필터 규칙

- 태그는 현장 유형과 공법을 함께 사용한다.
- 여러 태그를 선택하면 선택한 모든 태그가 있는 사례만 보여준다.
- 검색창은 제공하지 않는다.
- `필터 초기화`는 모든 선택 태그를 해제하고 ID 내림차순 전체 목록의 1페이지를 보여준다.

## 2. 사용 제품

별도 `products.json`은 만들지 않는다. 사용 제품 목록과 필터는 모든 사례의 `productIds` 값을 모아 만든다. 현재 사용 제품명은 `크리트`, `MMA`, `비노출 방수`처럼 사례 데이터에 기록된 값을 그대로 표시한다.

### 제품 필터 규칙

- 첫 필터 칩 `전체`는 선택 자재를 모두 해제하고 전체 제품을 보여준다. 그 밖의 칩은 `productIds`에 있는 제품명이다.
- 제품 목록에는 별도 `필터 초기화` 버튼을 두지 않는다.
- 카드에는 제품명, 준비된 이미지 또는 이미지 준비 중 안내, 해당 제품이 쓰인 현장 안내, `시공 사례 보기` 링크를 표시한다.
- 카드의 `시공 사례 보기` 링크는 해당 제품명을 사례 필터의 선택값으로 설정하고 `/cases`로 이동한다.
- 제품 상세 주소·상세 페이지는 제공하지 않는다.
- 제품 판매·가격·장바구니·다운로드 기능은 제공하지 않는다.

## 3. 사이트 정보 (`content/site.json`)

| 필드 | 초기값 | 교체 시점 |
| --- | --- | --- |
| companyName | `GK 산업` | 확정 |
| phone | `1588-0000` | 실제 대표번호 확보 시 |
| serviceArea | `대한민국 전국` | 확정 |
| address | 임시 주소 | 실제 주소 확보 시 |
| businessInfo | 임시 사업자 정보 | 실제 정보 확보 시 |
| social.youtube | `null` | 실제 주소 확보 시 |
| social.instagram | `null` | 실제 주소 확보 시 |
| keywords | 바닥 시공, 에폭시 바닥, 우레탄 바닥, MMA 바닥 등 | 검색 전략 변경 시 |
| about.title | 임시 회사 소개 제목 | 실제 소개 방향 확정 시 |
| about.paragraphs | 임시 회사 소개 문단 배열 | 실제 소개 문구 확정 시 |

회사 소개 문구는 UI 코드에 직접 쓰지 않고 `about` 데이터로 관리한다. 실제 실적·인증·연혁이 확인되기 전에는 임시 예시 문구를 사용한다. 외부 채널 URL이 `null`이면 화면에는 `준비 중`으로 표시하고 링크는 만들지 않는다.

## 인계

- 완료: 사례·제품·사이트 정보의 JSON 기준 정의
- 확정: 다중 AND 필터, 숫자 ID 내림차순, 고객 화면 ID 숨김, 제품 카드의 사례 연결
- 미확정: 실제 사진, 제품 사양, 회사 정보, 외부 채널 주소
- 다음 역할 입력: 디자인에 필요한 사례·제품 카드 정보
- 다음 행동: 기획 리뷰 통과 후, 사용자의 디자인 단계 진행 승인을 기다린다.
