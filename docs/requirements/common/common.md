# REQ-common-001

- 유형: REQ
- 영역: common
- 상태: DECIDED
- 우선순위: 상
- 제목: 대표 전화번호를 통한 문의 시작

## 요구사항

모든 주요 공개 화면은 방문자가 공개 확정된 대표 전화번호를 확인하고 전화 문의를 시작할 수 있게 한다.

## 이유

전화 문의는 이 서비스의 상담 전환 경로이므로, 탐색 중인 방문자가 언제든 문의를 시작할 수 있어야 한다.

## 완료 기준

- 홈, 시공 사례, 제품 소개, 회사 소개에서 대표 전화번호를 확인할 수 있다.
- 모바일에서 방문자가 전화 문의를 선택하면 공개 확정된 대표 전화번호로 연결된다.
- 데스크톱에서는 대표 전화번호를 표시하며, 전화 연결 동작은 제공하지 않는다.
- 대표 전화번호가 확정되기 전에는 전화 연결을 제공하지 않고, 전화번호가 준비되지 않았음을 표시한다.

# REQ-common-004

- 유형: REQ
- 영역: common
- 상태: DECIDED
- 우선순위: 상
- 제목: 주요 공개 영역 간 이동 제공

## 요구사항

방문자는 어느 주요 공개 화면에서든 홈, 시공 사례, 제품 소개, 회사 소개로 이동할 수 있어야 한다.

## 이유

방문자가 핵심 정보를 확인하거나 문의를 시작하기 위해 이전 화면을 반복해서 탐색하지 않아야 한다.

## 완료 기준

- 홈, 시공 사례, 제품 소개, 회사 소개 화면마다 네 공개 영역으로 이동하는 경로가 있다.
- 현재 표시 중인 공개 영역을 사용자가 구분할 수 있다.
- 이동 경로를 선택하면 선택한 공개 영역으로 이동한다.
- 전화 문의는 네 공개 영역과 별도로 모든 주요 공개 화면에서 제공한다.

------------------------

# REQ-common-005

- 유형: REQ
- 영역: common
- 상태: DECIDED
- 우선순위: 상
- 제목: 공개 확정 회사 정보의 일관된 표시

## 요구사항

대표 전화번호, 회사명, 주소, 사업자 정보는 공개가 확정된 값만 표시하고, 같은 정보는 모든 표시 위치에서 동일하게 제공한다.

## 이유

회사 정보의 불일치 또는 추정 정보는 방문자의 신뢰를 훼손할 수 있다.

## 완료 기준

- 공개 확정되지 않은 회사 정보는 표시하지 않는다.
- 대표 전화번호, 회사명, 주소, 사업자 정보를 공개한다.
- 대표 전화번호, 회사명, 주소, 사업자 정보가 여러 위치에 표시될 경우 값이 서로 일치한다.
- 회사 정보가 변경되면 모든 표시 위치에서 변경된 값을 확인할 수 있다.

------------------------

# REQ-common-006

- 영역: common
- 상태: DECIDED
- 우선순위: 상
- 제목: 실제 근거가 있는 콘텐츠 제공

## 요구사항

시공 사례, 제품, 회사 정보에는 공개가 확정된 실제 콘텐츠만 사용한다.

## 이유

실제 시공 결과와 제품 정보는 방문자가 업체 신뢰와 시공 가능성을 판단하는 근거다.

## 완료 기준

- 제공되지 않은 고객사, 수상, 인증, 경력, 시공 건수, 후기, 주소, 전화번호, SNS 주소를 표시하지 않는다.
- 실제 콘텐츠가 준비되지 않은 항목은 실제 정보처럼 보이는 대체 문구나 이미지를 사용하지 않는다.
- 사례 위치 정보는 공개가 허용된 범위만 표시한다.

# REQ-common-009

- 영역: common
- 상태: REJECTED
- 우선순위: 중
- 제목: 이미지 미제공 상태 안내

## 요구사항

이미지가 준비되지 않은 콘텐츠는 사용자에게 이미지 미제공 상태를 안내한다.

## 이유

이미지 영역이 비어 있으면 서비스 오류로 오해될 수 있으므로 현재 상태를 명확히 알려야 한다.

## 완료 기준

- 이미지가 없는 콘텐츠의 이미지 영역에 `해당 이미지는 준비 중입니다.`를 표시한다.
- 이미지 미제공 안내는 사진 열기 또는 외부 이동을 실행하는 조작 요소가 아니다.

# NFR-common-001

- 유형: NFR
- 영역: common
- 상태: DECIDED
- 우선순위: 상
- 제목: 정적 프론트엔드 범위 유지

## 요구사항

초기 서비스는 정적 HTML·CSS·JavaScript·이미지로 배포 가능한 프론트엔드로 제공하며, 백엔드·데이터베이스·서버 API 및 요청 시점 서버 기능을 포함하지 않는다.

## 이유

첫 출시 범위를 홍보 웹사이트에 필요한 기능으로 제한하기 위해서다.

## 완료 기준

- 사용자 계정, 결제, 관리자, 파일 업로드, 온라인 문의 접수를 제공하지 않는다.
- 사용자 입력 데이터를 서버 또는 데이터베이스에 저장하지 않으며, 사용자별·요청별 데이터 처리와 인증을 제공하지 않는다.
- 서버 액션과 동적 서버 API를 제공하지 않는다.
- 공개 콘텐츠와 공개 URL은 빌드 시점에 결정할 수 있으며, 공개 콘텐츠는 화면 코드와 분리해 관리한다.
- 정적 결과물 배포 후에는 `REQ-common-021`에서 확정한 공개 화면과 404 화면을 제공한다.

------------------------

- 화면 폭 `360px`, `768px`, `1280px`에서 대표 전화번호를 확인할 수 있다.
- 화면 폭 `360px`, `768px`, `1280px`에서 핵심 정보와 조작 요소가 화면 밖으로 잘리지 않는다.

# NFR-common-004

- 유형: NFR
- 영역: common
- 상태: REJECTED
- 우선순위: 중
- 제목: 실제 공개 정보에 근거한 검색·공유 정보 제공

## 요구사항

공개 페이지는 실제 공개 콘텐츠와 실제 배포 주소에 근거한 검색·공유 정보를 제공한다.

## 이유

검색 결과나 공유 미리보기가 실제 서비스와 다른 정보를 전달하면 방문자의 신뢰를 해칠 수 있다.

## 완료 기준

- 각 공개 페이지의 제목과 설명은 해당 페이지의 실제 콘텐츠를 설명한다.
- 각 공개 페이지는 공유 시 실제 콘텐츠를 설명하는 제목·설명을 제공하고, 실제 대표 이미지가 있는 경우에만 해당 이미지를 제공한다. 대표 이미지 미제공 기준은 NFR-common-020을 따른다.
- 실제 배포 도메인이 확정되기 전에는 임의의 도메인을 검색·공유 정보에 사용하지 않는다.
- 실제 배포 도메인이 확정된 뒤에 공개 URL 목록과 검색 로봇 안내를 제공한다.

------------------------

- 우선순위: 상
- 제목: 공통 헤더의 전화 문의 CTA 미제공

## 요구사항

홈, 시공 사례 목록, 사용 제품, 회사 소개의 공통 헤더에는 기본 탐색 메뉴와 공식 외부 채널 접근 경로만 제공하며, 전화 문의 CTA는 표시하지 않는다. 전화 문의는 각 화면의 히어로 영역과 데스크톱·태블릿에서 히어로를 지난 뒤 표시하는 오른쪽 CTA로 제공한다. 모바일에는 오른쪽 CTA를 표시하지 않는다.

## 이유

헤더는 기본 탐색에 집중하고, 전화 문의는 히어로와 데스크톱·태블릿의 스크롤 뒤 오른쪽 CTA로 일관되게 제공하기 위해서다.

## 완료 기준

- 홈, 시공 사례, 제품 소개, 회사 소개 화면에 동일한 공통 헤더가 표시된다.
- 공통 헤더에서 홈, 시공 사례, 제품 소개, 회사 소개로 이동할 수 있다.
- 공통 헤더에서 공식 YouTube와 Instagram으로 이동할 수 있다.
- 공통 헤더에는 전화 문의 CTA를 표시하지 않는다.
- 각 공개 화면의 히어로 전화 문의 CTA는 REQ-common-023을 따른다.
- 데스크톱·태블릿의 히어로 이탈 뒤 오른쪽 전화 문의 CTA와 모바일 미표시는 REQ-common-026을 따른다.

# REQ-common-018

- 영역: common

- 제목: 공식 외부 채널 링크의 새 탭 이동

## 요구사항

YouTube와 Instagram 접근 경로를 선택하면 공식 외부 채널 URL을 새 탭에서 열고, 현재 사이트 화면은 유지한다.

## 이유

- Instagram 접근 경로를 선택하면 공식 Instagram 프로필 URL이 새 탭에서 열린다.
- 외부 채널을 연 뒤에도 기존 사이트 화면은 유지된다.
- YouTube와 Instagram 링크의 접근 가능한 이름에는 채널명과 `새 탭 열기`를 포함한다.
- 화면에는 새 탭 이동을 위한 별도 텍스트 또는 아이콘을 추가하지 않는다.

필터 조건이 바뀐 뒤 이전 페이지나 목록 중간 위치를 유지하면 방문자가 새 결과의 개수와 첫 제품을 놓칠 수 있다.

## 완료 기준

- 제품 필터 칩을 선택하거나 `전체`를 누르면 현재 페이지 번호를 1페이지로 초기화한다.
- 필터 변경 뒤 `전체 N건 / 1페이지` 제품 결과 요약이 고정 헤더에 가려지지 않도록 화면 상단에 표시된다.
- 제품 결과 요약 바로 아래에서 새 조건의 첫 제품 카드 또는 결과 없음 안내를 확인할 수 있다.
- 선택된 제품 필터 칩 또는 `전체` 칩은 필터 변경 뒤에도 그대로 표시된다.

# REQ-common-041

- 유형: REQ
- 영역: common
- 상태: DECIDED
- 우선순위: 중
- 제목: 사례·제품 목록의 동일한 페이지당 표시 수

## 요구사항

시공 사례(`/cases`)와 사용 제품(`/products`) 목록은 PC·태블릿·모바일에서 모두 한 페이지에 카드 4개씩 표시한다. 두 목록의 카드 수가 4개를 초과하면 같은 페이지 번호 이동 방식으로 다음 카드 묶음을 표시한다.

## 이유

사례와 제품 목록을 같은 카드 밀도와 페이지 이동 방식으로 제공해, 방문자가 목록마다 다른 기준을 새로 익히지 않게 한다.

## 완료 기준

- `/cases`와 `/products`는 각 화면 폭에서 한 페이지에 최대 카드 4개를 표시한다.
- 두 목록 모두 5개 이상일 때 현재 페이지, 이전·다음 페이지, 페이지 번호 이동을 제공한다.
- 화면 폭이 바뀌어도 한 페이지당 카드 수는 4개로 유지하고, 카드 열·여백만 디자인 시스템 기준으로 재배치한다.
- 제품 필터 변경 뒤에는 REQ-common-040에 따라 1페이지의 최대 4개 카드 또는 결과 없음 안내를 표시한다.
