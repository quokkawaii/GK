# requirements 폴더 구조

requirements  
├─ common # 공동 요구사항
| └─ common.md # 이안에 요구사항들을 정리
└─ 사용자 또는 ai의 요청사항에 인해 폴더 생성 (페이지마다 있음)

- brief.md와 PRD.md 파일은 추후 삭제 예정이다.

# 요구사항 종류

- REQ: 기능 요구사항
- NFR: 비기능 요구사항

# 요구사항 상태

- TBD: 아직 결정되지 않음
- DECIDED: 결정 완료
- REJECTED: 채택하지 않음
- SUPERSEDED: 다른 요구사항이나 결정으로 대체됨

# 이름 규칙

- REQ-{영역}-{번호}
- NFR-{영역}-{번호}

예:

- REQ-common-001
- REQ-cases-001
- NFR-common-001

# 작성 규칙

- 하나의 요구사항은 하나의 독립적이고 검증 가능한 사용자 행동 또는 시스템 조건을 정의한다. 세부 검증 항목은 여러 개의 완료 기준으로 작성할 수 있다.
- 대상, 동작, 기준값을 구체적으로 작성한다.
- 이유와 완료 기준을 함께 기록한다.
- 구현 방법이 아니라 사용자가 확인할 수 있는 결과를 작성한다.
- 번호는 삭제 후에도 재사용하지 않는다.
- 파일명 변경 시 요구사항 ID는 변경하지 않는다
- 우선 순위를 하,중,상으로 표시한다.

예 :

```txt

# REQ-common-001

- 유형: REQ
- 영역: common
- 상태: DECIDED
- 우선순위: 상
- 제목: 모든 페이지에서 전화 문의 경로 제공

## 요구사항

모든 페이지는 사용자가 대표 전화번호를 확인하고 전화 연결을 실행할 수 있는 전화 문의 경로를 제공한다.

## 이유

GK 홈페이지의 주요 전환 목표가 방문자의 전화 문의이므로, 사용자가 어느 페이지에 있더라도 문의 행동에 빠르게 접근할 수 있어야 한다.

## 완료 기준

- 모든 페이지의 헤더에 전화 문의 버튼이 표시된다.
- 모바일에서 전화 문의 버튼을 누르면 대표 전화번호로 전화 연결을 실행할 수 있다.
- 데스크톱에서는 전화 문의 버튼을 통해 대표 전화번호를 확인할 수 있다.
- 대표 전화번호가 변경되어도 요구사항 문서나 UI 구조를 다시 정의하지 않고 콘텐츠 값만 교체할 수 있다.

------------------------------------------------------------------------------------------------------------------------

```

# 공식 문서 참고시

- 절대 요구사항의 상태를 DECIDED로 만들면 안됨
