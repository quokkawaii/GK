# 오류와 주소 이동 대응

## 사용자에게 보이는 오류

| 상황 | 대응 | 사용자 동선 |
| --- | --- | --- |
| 존재하지 않는 주소 | 404 안내 화면 | 홈 또는 시공 사례 목록 |
| 화면을 표시하는 중 코드 오류 | 일반 오류 화면 | 다시 시도, 홈 또는 시공 사례 목록 |
| 사이트 전체 화면 복구가 필요한 오류 | 전체 오류 화면 | 홈으로 이동 |
| JSON 콘텐츠 오류 | 빌드 중단, 사용자 보고 | 잘못된 데이터 수정 승인 후 재빌드 |

## HTTP 상태 구분

- **300번대**: 오류라기보다 주소가 다른 곳으로 이동했다는 뜻이다. 초기 사이트에서는 주소 이동을 만들지 않는다. 나중에 주소를 바꿀 때만 이전 주소와 새 주소를 기록하고 사용자 승인 후 설정한다.
- **404**: 요청한 주소에 해당하는 페이지가 없을 때 사이트가 직접 안내한다.
- **500번대**: 일반 서버가 없는 정적 사이트에서는 사이트 코드가 500 응답을 만들지 않는다. 호스팅 서비스 자체의 장애는 호스팅 서비스가 처리하며, 브라우저에서 화면을 그리는 중 발생한 오류는 사이트의 일반 오류 화면으로 안내한다.

## 수정 승인 규칙

오류가 발견되면 개발자는 오류 내용, 영향, 원인 추정, 수정하려는 파일과 조치를 먼저 사용자에게 보고한다. 사용자 승인 전에는 수정하거나 반복적으로 재시도하지 않는다.

## 초기 제외 도구

Sentry 등 외부 오류 추적 서비스는 초기 범위에서 사용하지 않는다. 오류 안내 화면, PR 자동 검사, Cloudflare Pages 빌드 로그로 먼저 운영하고 실제 필요가 확인되면 별도 승인 후 검토한다.
