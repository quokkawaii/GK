시공 사례 상세 아키텍처

이 문서는 “부모는 화면을 합치기만 하고, 각 화면은 자기에게 필요한 기능을 직접 가져온다”는 기준으로 만든 구조도입니다. 복잡해진 화면은 같은 규칙으로 한 단계 더 나눌 수 있습니다.

정한 규칙: 부모 CaseDetailModal은 세 화면을 배치하고 필요한 데이터만 넘깁니다. 부모는 팝업 제어, 스크롤 잠금, 사진 이동을 구현하거나 가져오지 않습니다. 각 자식 화면이 자기 기능을 직접 import합니다.

1. 지금은 어떻게 되어 있는가

현재는 하나의 파일 안에 화면과 기능이 전부 들어 있습니다.

한 파일에 모든 일이 몰린 구조

src/features/cases/components/CaseDetailModal.tsx

CaseDetailModal.tsx
  • 팝업 틀과 닫기 버튼을 그림
  • 사진, 이전·다음 버튼, 썸네일을 그림
  • 큰 사진 보기 화면을 그림
  • 시공 내용·장소·제품·태그를 그림
  • Escape·Tab 키와 초점 이동을 처리
  • 뒤 화면 스크롤을 잠그고 되돌림
  • 현재 사진 번호와 큰 사진 보기 상태를 기억

문제: 화면 하나를 고치려고 해도 기능 코드까지 함께 읽어야 합니다. 다른 화면이 같은 기능을 쓰려면 다시 만들게 됩니다.

2. 앞으로 만들 구조

부모는 화면 1·2·3만 합칩니다. 각 화면은 자기 책임과 기능을 가집니다.

아래에서 파란 상자는 “그 화면이 직접 import해서 쓰는 기능”입니다. 화살표는 부모가 화면을 배치하는 방향입니다.

CaseDetailModal.tsx

부모: 상세 화면을 합치는 파일

CaseDialogScreen, CaseImageScreen, CaseInformation을 순서대로 배치합니다.
사례 데이터와 닫기 동작만 자식에게 전달합니다.

화면 1: 팝업 틀

CaseDialogScreen.tsx

팝업의 배경, 제목, 닫기 버튼, 자식 화면이 들어갈 자리를 그립니다.

더 복잡해지면CaseDialogHeader와 CaseDialogBackdrop처럼 화면 1-1, 1-2로 다시 나눌 수 있습니다.
화면 1이 직접 import하는 기능useDialogFocus
Escape·Tab·처음/마지막 초점 처리useBodyScrollLock
팝업이 열린 동안 뒤 화면 스크롤 잠금

화면 2: 사진 영역

CaseImageScreen.tsx

현재 사진, 이전·다음 버튼, 사진 순서, 썸네일을 보여 줍니다.

더 복잡해지면CaseMainImage, CaseImageControls, CaseImageThumbnails처럼 화면 2-1, 2-2, 2-3으로 나눕니다.
화면 2가 직접 import하는 기능useImageGallery
현재 사진 선택·이전·다음·썸네일 선택useImageViewer
큰 사진 보기 열기·닫기

화면 3: 시공 정보

CaseInformation.tsx

시공 내용, 장소, 사용 제품, 태그를 보여 줍니다. 사진과 팝업을 제어하지 않습니다.

더 복잡해지면CaseDescription, CaseMetadata처럼 화면 3-1, 3-2로 나눌 수 있습니다.
화면 3이 직접 import하는 기능현재는 없음 — 받은 사례 정보를 화면에 표시만 합니다.

4. 다른 화면에서도 어떻게 쓰는가

예를 들어 나중에 모바일 메뉴가 팝업처럼 열리면, 사례 상세의 코드를 가져오는 것이 아니라 필요한 기능 파일만 직접 가져옵니다.

이번 구조에서 확정할 기준

CaseDetailModal은 부모 조립 파일입니다. 기능을 직접 구현하지 않습니다. CaseDialogScreen, CaseImageScreen, CaseInformation은 각각 자기 화면을 그리고, 필요한 기능은 각자 직접 import합니다. 화면이 커지면 해당 화면 안에서 1-1, 1-2처럼 더 나눕니다.
