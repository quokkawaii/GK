GK 산업 프로젝트 운영 규칙

모든 역할과 단계에 공통으로 적용되는 작업 기준입니다.

01. 목적과 범위02. 작업 단계와 승인03. 역할과 책임04. 결정·변경 관리05. 데이터·기술 경계06. 품질과 검토07. 실패·충돌 처리

1목적과 범위

  • GK 산업의 바닥 시공 소개·홍보 웹사이트 프로젝트다.
  • 시공 사례와 사용 제품 정보를 통해 전화 문의로 연결한다.
  • 사용자가 제공하고 승인한 사실만 사용하며, 모르는 내용은 사실처럼 채우지 않는다.

2작업 단계와 사용자 승인

  1. 인터뷰
  2. 기획
  3. 디자인
  4. 구현 계획
  5. 개발
  6. 리뷰
  7. 배포
사용자의 명시적 승인 없이는 다음 단계로 넘어가지 않습니다. 인터뷰·기획·디자인 중에는 앱 코드, 의존성, 데이터베이스, 배포 환경을 변경하지 않습니다.

역할책임산출물
기획자인터뷰, 요구사항, 콘텐츠 모델, 사용자 흐름기획 문서

역할별 실행 지침은 .codex/agents/*.toml에서 관리합니다. 역할 간 의견이 다르면 사용자가 결정합니다.

4결정·미확정 사항·변경 관리

  • 중요한 사용자 승인은 결정 기록에 남긴다.
  • 미확정 정보는 [TBD-번호]와 해결 질문을 함께 기록한다.
  • 요구사항·결정·리뷰 지적에는 REQ, DEC, REV 식별자를 사용한다.
  • 기존 산출물 변경 시 변경 항목과 이유를 간단히 보고한다.

5데이터와 기술 경계

  • 초기 콘텐츠는 정적 JSON으로 관리한다. DB·MongoDB·REST API는 별도 승인 전 도입하지 않는다.
  • 시공 사례는 여러 장의 사진과 사례명, 태그, 장소, 내용, 공법, 사용 제품을 지원한다.
  • 사용 제품은 판매가 아닌 사용 목적·장점·구성·시공 기준·시공 가능 면적을 소개한다.
  • 검색어와 예시 콘텐츠는 코드와 분리한다.
  • 승인 없이 별도 하위 프로젝트 폴더를 만들지 않는다.

6품질과 검토 기준

  • 시공 사례 사진을 주요 콘텐츠로 노출한다.
  • 전화 문의 동선을 첫 화면과 주요 페이지에서 쉽게 찾게 한다.
  • 반응형, 키보드 접근성, 대체 텍스트, 성능을 점검한다.
  • SEO 기본 항목: 제목·설명, 의미 있는 URL, 사이트맵, robots, 구조화된 업체 정보.

7실패·충돌 처리

  • 같은 오류로 같은 도구나 검증을 반복하지 않는다. 두 번의 실질적 수정 시도 후에는 사용자에게 보고한다.
  • 기존 검증 도구가 있을 때만 실행하고, 없는 도구를 임의로 만들지 않는다.
  • 충돌 시 쟁점, 관련 ID, 선택지별 이득·비용, 추천안을 제시하고 사용자 결정을 기다린다.
