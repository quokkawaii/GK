# NFR-common-009

- 우선순위: 상
- 제목: HTTPS 대표 공개 주소 제공
- 개발 상태: 미확인

## 개발 방법

첫 출시의 대표 공개 도메인을 배포 전에 확정하고 HTTPS로만 제공한다. 대표 공개 주소가 아닌 주소의 이동은 정적 결과물을 제공하는 호스팅 환경에서 처리한다.

- 대표 공개 도메인이 배포 전에 확정된다.
- 대표 공개 주소는 HTTPS를 사용한다.
- 호스팅 환경에서 HTTP 또는 대표 공개 주소가 아닌 주소를 대표 공개 주소로 이동한다.
- 대표 공개 주소와 검색·공유 정보에 사용하는 주소가 일치한다.

# NFR-common-033

- 우선순위: 중
- 제목: GitHub 연동 Cloudflare 자동 재배포 사용
- 개발 상태: 미확인

## 개발 방법

GitHub의 Cloudflare 배포 연결 브랜치가 변경되면 Cloudflare 자동 재배포를 사용한다. 콘텐츠·이미지·회사 정보·검색·공유 자산 변경 후 별도 캐시 삭제, 반영 시간 목표, 화면·공유 미리보기 확인 절차는 제공하지 않는다.

- GitHub의 배포 연결 브랜치 변경이 Cloudflare 자동 재배포를 시작한다.
- HTML, 이미지, 아이콘, Open Graph 이미지에 별도 캐시 정책·캐시 삭제 절차·반영 시간 목표를 두지 않는다.
- 배포 뒤 대표 화면과 공유 미리보기에서 변경값을 별도로 확인하지 않는다.

# NFR-common-036

- 우선순위: 중
- 제목: Cloudflare Pages 운영 배포 브랜치
- 개발 상태: 미확인

## 개발 방법

Cloudflare Pages의 대표 도메인 운영 배포는 GitHub `main` 브랜치 변경으로만 시작한다.

- GitHub `main` 브랜치 변경이 Cloudflare Pages 대표 도메인 운영 배포를 시작한다.
- `main` 이외의 브랜치 변경은 대표 도메인 운영 배포를 시작하지 않는다.
- NFR-common-033의 GitHub 연동 자동 재배포 기준은 `main` 브랜치에 적용한다.

# NFR-common-050

- 우선순위: 중
- 제목: Cloudflare Pages 미리보기 자동 배포 미제공
- 개발 상태: 미확인

## 개발 방법

Cloudflare Pages에서 `main` 이외 브랜치의 자동 미리보기 배포를 제공하지 않는다.

- `main` 이외 브랜치 변경은 Cloudflare Pages 미리보기 배포를 시작하지 않는다.
- `main` 이외 브랜치에 연결된 공개 미리보기 URL을 제공하지 않는다.
- 미리보기 URL을 위한 Cloudflare Access 정책과 `X-Robots-Tag: noindex` 검수는 제공하지 않는다.
- 대표 sitemap·canonical·공유 대상 URL에는 `main`에서 배포한 대표 도메인 URL만 사용한다.

------------------------

# NFR-common-037

- 우선순위: 상
- 제목: 대표 공개 URL의 끝 슬래시 미사용
- 개발 상태: 미확인

## 개발 방법

홈을 제외한 대표 공개 URL은 끝 슬래시 없이 사용한다. `/cases/`, `/cases.html`, `/cases/index.html`처럼 같은 공개 페이지를 가리키는 변형 주소는 끝 슬래시 없는 대표 URL로 301 이동한다.

- 시공 사례와 제품 소개, 회사 소개의 대표 URL은 각각 끝 슬래시 없는 주소로 제공한다.
- `/cases/`, `/cases.html`, `/cases/index.html` 요청은 `/cases`로 301 이동한다. 다른 공개 페이지도 같은 규칙을 적용한다.
- NFR-common-019의 canonical, NFR-common-040의 sitemap, NFR-common-039의 내부 링크에는 끝 슬래시 없는 대표 URL만 사용한다.

------------------------

# NFR-common-051

- 우선순위: 상
- 제목: 비대표 도메인 이동 시 경로·쿼리 문자열 전체 보존
- 개발 상태: 미확인

## 개발 방법

`www.대표도메인` 및 `<프로젝트>.pages.dev`에서 대표 도메인으로 301 이동할 때, 요청 경로와 쿼리 문자열을 모두 대표 도메인 URL에 보존한다.

- `www.대표도메인/cases?source=naver` 요청은 `대표도메인/cases?source=naver`로 301 이동한다.
- `<프로젝트>.pages.dev/products?source=naver` 요청은 `대표도메인/products?source=naver`로 301 이동한다.
- 이동 뒤 URL 경로는 NFR-common-037의 끝 슬래시 없는 URL 형식과 일치한다.
- 대표 sitemap·canonical에는 쿼리 문자열이 없는 기본 대표 URL만 사용한다.

------------------------

# NFR-common-040

- 우선순위: 중
- 제목: 대표 공개 페이지 4개의 검색 로봇·sitemap 제공
- 개발 상태: 미확인

## 개발 방법

대표 도메인이 확정된 뒤에는 홈(`/`), 시공 사례(`/cases`), 제품 소개(`/products`), 회사 소개(`/about`) 4개 대표 공개 페이지의 검색 로봇 안내와 sitemap을 정적 자산으로 제공한다.

- `robots.txt`는 대표 도메인 루트에서 제공하고 sitemap의 대표 URL을 안내한다.
- sitemap은 대표 도메인의 절대 URL만 포함하며, 홈·시공 사례·제품 소개·회사 소개의 canonical URL만 포함한다.
- 필터 결과, 시공 사례 상세 팝업, 404·오류 화면, `pages.dev`, 미리보기 URL은 sitemap에 포함하지 않는다.
- `robots.txt`의 차단 규칙만으로 색인 제외를 처리하지 않으며, 색인 제외가 필요한 공개 URL은 실제 404 응답 또는 `noindex`로 처리한다.

------------------------

# NFR-common-041

- 우선순위: 중
- 제목: 유효하지 않은 공개 주소의 실제 404 응답
- 개발 상태: 미확인

## 개발 방법

제공하지 않는 공개 주소는 REQ-common-019의 안내 화면과 함께 HTTP 404 응답으로 제공하며, 정적 배포에서 홈 화면을 200 응답으로 대신 제공하지 않는다.

- 제공하지 않는 공개 주소 요청은 HTTP 404 상태로 응답한다.
- 정적 결과물에는 최상위 404 결과물이 포함된다.
- 존재하지 않는 주소가 홈 화면 또는 다른 정상 공개 화면으로 200 응답되지 않는다.
- REQ-common-019의 홈 복귀 버튼은 404 화면에서 계속 제공한다.

# NFR-common-042

- 우선순위: 상
- 제목: 자체 도메인만 허용하는 정적 응답 보안 헤더
- 개발 상태: 미확인

## 개발 방법

NFR-common-024의 보안 정책을 구체화해, 정적 공개 응답에는 자체 도메인 자산만 허용하는 콘텐츠 보안 정책과 프레임 삽입 방지, 콘텐츠 형식 추측 방지, 참조 정보 전송, 브라우저 기능 제한 헤더를 적용한다.

- `Content-Security-Policy`는 `default-src 'self'`, `script-src 'self'`, `style-src 'self'`, `img-src 'self'`, `font-src 'self'`, `connect-src 'self'`, `frame-src 'none'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`을 적용한다.
- 외부 스크립트·스타일·이미지·글꼴·연결 자원, iframe 삽입, 플러그인 객체는 허용하지 않는다. 유튜브·인스타그램의 일반 외부 링크 이동은 콘텐츠 보안 정책으로 제한하지 않는다.
- `frame-ancestors 'none'`으로 다른 사이트의 프레임 삽입을 막는다.
- `X-Content-Type-Options: nosniff`를 적용한다.
- `Referrer-Policy: strict-origin-when-cross-origin`을 적용해 다른 도메인으로 이동할 때 대표 도메인 정보만 전달한다.
- `Permissions-Policy: camera=(), geolocation=(), microphone=()`을 적용한다.
- 적용한 헤더는 정적 HTML, CSS, JavaScript, 이미지, 404 응답에 일관되게 제공한다.
- 서버 함수 응답에는 `_headers`가 적용되지 않는다는 전제에서, NFR-common-001의 정적 프론트엔드 범위를 유지한다.

------------------------

# NFR-common-049

- 우선순위: 중
- 제목: 루트 대표 도메인의 Cloudflare zone DNS 연결
- 개발 상태: 미확인

## 개발 방법

나중에 구매할 루트 대표 도메인을 Cloudflare zone에 추가하고, 도메인 구매처의 네임서버를 Cloudflare가 지정한 네임서버로 변경한 뒤 Cloudflare Pages의 대표 도메인으로 연결한다.

- 대표 공개 주소는 나중에 구매할 루트 도메인이다.
- 해당 도메인은 Cloudflare zone에 추가하고, 도메인 구매처에서 Cloudflare가 지정한 네임서버로 연결한다.
- Cloudflare Pages 프로젝트에는 네임서버 연결이 완료된 루트 대표 도메인을 연결한다.
