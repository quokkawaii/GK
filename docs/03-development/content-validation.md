# 콘텐츠 데이터 검사

개발 단계에서 빌드 전에 `content/` JSON 파일을 읽어 아래 항목을 확인한다. 이 검사는 서버나 외부 서비스 없이 파일 내용을 한 번 확인하는 가벼운 기능이다.

## 검사 항목

| 대상 | 확인 내용 |
| --- | --- |
| 사례 JSON 루트 | `content`가 비어 있지 않은 배열인지 |
| 시공 사례 (`content`) | `id`가 양의 정수이고 중복되지 않는지 |
| 시공 사례 (`content`) | `thumbnailIndex`가 `images` 배열 범위 안인지 |
| 시공 사례 (`content`) | 제목, 태그, 장소, 사진 경로 등 필수 정보가 비어 있지 않은지 |
| 시공 사례 (`content`) | `productIds`가 비어 있지 않은 배열인지 |
| 사이트 정보 | 대표 전화번호, 활동 지역, 검색어 배열 등 필수 정보가 비어 있지 않은지 |
| 사이트 정보 | 주소·사업자 정보·외부 채널 URL은 `null` 또는 문자열인지 |

시공 사례는 유효한 숫자 `id`를 기준으로 내림차순 정렬한다. ID 자체는 고객 화면에 표시하지 않는다.

## 문제 발견 시 처리

검사에 실패하면 개발자는 자동으로 데이터를 고치지 않는다. 실패한 항목, 사용자 화면·배포에 미치는 영향, 원인 추정, 수정하려는 파일과 조치를 사용자에게 먼저 보고하고 승인받은 뒤에만 수정한다.

## 사진 용량

사진 추가 시 자동 변환·압축은 하지 않는다. 특정 사진이 지나치게 커서 페이지 로딩에 영향을 줄 때만 해당 파일을 보고하고, 사용자 승인 후에만 축소한다.
