# review 폴더 & 파일 생성 규칙

- 오늘 날짜를 기준으로 폴더가 없다면 생성한다. 생성 규치은 YY-MM-DD-review와 같다.
- 현재 작업중인 리뷰어에 의해 오늘 날짜를 기준으로 만든 폴더에 파일이 없다면 만든다. 예 : 리뷰어가 기획 리뷰 생성시 -> YY-MM-DD-plan.md
- 리뷰어는 사용자에 의해 특정 파일 & 화면 등을 리뷰하며, 무엇을 리뷰했는지와 리뷰 결과 등을 문서화 한다.
- 이 중에 문제가 있는 리뷰의 결과는 위험도로 표시하며 pass가 아닌 문서들은 issue-register.md에 작성한다.

# review 작성 규칙

- 야래는 review의 작성 규칙이다.

```md
## PLAN-REV-002 <!-- 역할 + REV + 번호 -->

- 내용: 홈 범위에 회사 소개
- 파일: `docs/requirements/brief.md`, `docs/requirements/site-map.md`
- 검사 내용 : 홈에 무슨 아이콘이 있는지 확인
- 발견된 문제점 : pass
- 심각도 : pass
- 출처 : 식별자를 적는다
```

# issue-register.md 파일 규칙

- 해당 파일은 리뷰를 통해 발견된 이슈를 저장하는 공간이다.
- 저장된 이슈는 사용자와의 인터뷰를 진행하여 문제점을 해결할 수 있다.
- 해결된 이슈는 즉시 해당 파일 내부에서 내용을 지우며, 해당 리뷰가 있는 페이지로 넘어가 pass 처리로 바꾼다.

# issue-register.md 작성 규칙

- 아래는 issue-register.md의 작성 규칙이다.
- 현재 날짜와 어디서 발생한 이슈인지를 적는다. (파일 추적이 쉽기 때문)

```md
## 26-08-12-dev-issues

- `DEV-REV-005` · 높음 · 분리된 상세 팝업과 모바일 메뉴의 실제 키보드 수동 검증이 남아 있다.
```
