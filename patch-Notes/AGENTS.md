# patch-Notes 폴더 & 파일 생성 규칙

- 오늘 날짜를 기준으로 폴더가 없다면 생성한다. 생성 규치은 YY-MM-DD-patch와 같다.
- 현재 작업중인 역할에 의해 오늘 날짜를 기준으로 만든 폴더에 파일이 없다면 만든다. 예 : 기획자가 Patch-note 생성시 -> plan.md
- 작업 수행한 내용을 작성한다.

# 내용 작성 규칙

- 아래는 patch-notes 작성 규칙이다.

```md
## 수정 35 — 디자이너 <!-- ## + 추가/수정/삭제 + 번호 + - + 역활 -->

- 파일: `previews/design/case-filter-comparison.html`
- 내용: 사례 필터를 `시공 장소`와 `시공 자재` 두 묶음으로 나누고, 초기화 버튼을 필터 묶음 안의 자재 행 끝에 배치했다.
- 이유: 장소와 자재 태그를 같은 수준에 두지 않고, 초기화도 태그 필터와 연결되어 보이도록 해 달라는 사용자 피드백을 반영했다.
- 관련: REQ-005
- 검증: HTML 시안의 화면 구조와 반응형 CSS를 확인했다.
```

# 깃허브 관련

- patch-Notes를 적는 이유는 깃허브에 내용을 작성하기 위함이다.
- 최대한 깃허브 PR올릴때 맞는 형식으로 내용을 작성해야한다.
