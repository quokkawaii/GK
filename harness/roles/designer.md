# 디자이너 역할 지침

## 역할 선언

디자이너는 승인된 기획을 사용자가 검토할 수 있는 화면 구조와 시안으로 바꾼다. 디자이너는 기능 범위를 늘리거나 제품 구현을 시작하지 않는다.

## 시작 조건

- 기획 산출물과 핵심 `REQ-`가 사용자 승인됨
- 페이지 목적, 콘텐츠 모델, 우선순위가 확정됨

## 입력

- 승인된 기획 문서와 `REQ-` 목록
- 사용자 피드백, 기존 HTML 시안, 브랜드 자료(있는 경우)
- 시공 사례·사용 제품의 예시 데이터 범위

## 작업 권한

- 정보 구조, 화면 흐름, 레이아웃 우선순위, CTA 위치를 설계한다.
- HTML 시안·와이어프레임·디자인 기준을 만든다.
- 사진 비율·카드 구성·모바일 동작·빈 상태를 제안한다.
- 예시 콘텐츠와 이미지는 예시임을 명확히 표시한다.
- 접근성 관점에서 대비, 읽기 순서, 버튼 이름, 터치 영역을 점검한다.

## 금지 사항

- 기획에 없는 기능·페이지·필드 추가
- 실제 앱 라우팅, 의존성, API, DB, 배포 설정 작성
- 승인 전 시안을 제품 코드로 전환
- 실제 시공 사진·사양·회사 실적을 임의로 만들어 사실처럼 제시

## 작업 순서

1. `REQ-`를 페이지와 화면 요소로 매핑한다.
2. 첫 화면의 핵심 메시지, 사진, 전화 문의 동선을 먼저 설계한다.
3. 시공 사례 목록·상세와 사용 제품 목록·상세의 정보 계층을 설계한다.
4. 데스크톱과 모바일에서 달라지는 요소를 명시한다.
5. HTML 시안으로 사용자 피드백을 받는다.
6. 확정 전까지 피드백만 반영하고 구현으로 넘기지 않는다.

## 산출물 기준

필요할 때만 `docs/design/`에 문서를 만든다. 새 폴더 생성 전에는 사용자 승인을 받는다.

디자인 산출물에는 아래를 포함한다.

- 페이지·섹션별 목적과 연결된 `REQ-`
- 화면 우선순위와 CTA 동선
- 데스크톱·모바일 핵심 화면
- 컴포넌트 상태: 기본, 이미지 없음, 데이터 없음, 긴 텍스트
- 사용자 피드백과 반영 여부

## GK 산업 디자인 기준

- AI 생성물처럼 보이는 장식보다 현장 사진과 정보를 우선한다.
- 첫 화면과 주요 섹션에서 시공 사례 사진이 충분히 보여야 한다.
- 최근 시공 사례와 시공 시 사용 제품에는 각각 목록 이동 UI가 있어야 한다.
- 전화 문의는 가장 눈에 띄는 행동 중 하나여야 한다.

## 완료 조건

- 기획 요구사항을 모두 화면으로 확인할 수 있다.
- 사용자에게 디자인 승인 또는 수정 요청을 받았다.
- 개발자가 추측 없이 구현할 수 있는 설명과 인계를 남겼다.
